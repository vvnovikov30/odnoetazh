## 6. Безопасность

### 6.1 Находки по приоритетам

| # | Находка | Где | Приоритет | Почему это важно |
|---|---|---|---|---|
| S1 | `requests.json` / `requests.txt` доступны по HTTP | `/requests.json` → **200**, `/requests.txt` → **200** | **P0** | Утечка ПДн (имя, телефон, email, IP, сообщение). 152-ФЗ, готовый список лидов для конкурентов, база для телефонного спама |
| S2 | Запись `requests.json` без блокировки | `send-email.php:158–162` | **P0** | `file_get_contents` → `json_decode(...) ?? []` → `file_put_contents`. При двух параллельных POST файл бьётся; следующий запрос читает битый JSON, получает `[]` и **перезаписывает историю одной записью**. Спам-залп = потеря всех заявок |
| S3 | `test-mail.php` в проде | `/test-mail.php` → **200** | **P1** | Публичный триггер `mail()` на боевой ящик + `php_uname()` / `phpversion()` |
| S4 | Мёртвые обработчики с `Cc: $email` и автоответом | `send-email_.php:166,204`, `send-email2.php:194,232` | **P1** | Любой бот POST’ом на эти URL инициирует отправку: письмо админу + письмо на указанный адрес. Это рефлексия почты: домен можно «прогреть» как источник спама и занести в чёрные списки — тогда реальные заявки перестанут доходить |
| S5 | Нет rate-limit по IP, нет проверки Origin/Referer | `send-email.php` | **P1** | CSRF-подобная рассылка с чужих сайтов; залп → переполнение ящика и диска |
| S6 | Нет honeypot-поля в формах | живой HTML: 0 вхождений `user_phone_check` | **P1** | Заявленный барьер №1 физически не может сработать |
| S7 | Дубли-страницы отдаются по URL | `/index1201.php`, `/blog_.php`, `/blog_comments.php` → **200** | **P2** | SEO-дубли, каннибализация запросов, раздувание индекса |
| S8 | `.htaccess` отсутствует | слепок хостинга | **P2** | Нет ни запрета на `.json/.txt/.md`, ни `X-Content-Type-Options`, ни запрета листинга каталогов |
| S9 | Двойное экранирование данных | `send-email.php:65–69` + `:173–185` | **P3** | В `requests.json` и письмах копятся `&quot;`/`&amp;` — искажение данных |
| S10 | `display_errors` не отключён в коде | все PHP | **P3** | Warning при записи файла попадёт в JSON-ответ и сломает `response.json()` на фронте: пользователь увидит ошибку, хотя заявка прошла |

### 6.2 Чего в коде **нет** (проверено)

- **нет** обработки загрузки файлов: `$_FILES` — 0 совпадений, `move_uploaded_file` — 0. File input в `index1201.php` — «мёртвая» фича, риска RCE нет;
- **нет** `eval`, `include($_GET)`, SQL-запросов вообще — инъекций в этом смысле нет;
- **нет** хардкода паролей/SMTP/API-ключей;
- **нет** счётчиков аналитики (Метрика/GA) — ни в main, ни в live. Предположение «на хостинге добавлены счётчики» **не подтвердилось**;
- **нет** CSRF-токена (для публичной формы не критично, но вместе с S5 позволяет накрутку).

### 6.3 Риск «тихой» потери заявки

Комбинация S2 + S10 + `@file_put_contents` (подавление ошибок) означает: при нехватке прав/диска запись **молча** не произойдёт, а пользователь всё равно увидит «Спасибо, заявка записана». Если `mail()` вернул `false`, добавляется приписка «Письмо не отправлено, но заявка записана» — при этом заявка может быть не записана вообще. Локально воспроизведено (на стенде без `sendmail`).

### Шаг 1 — переписать `send-email.php` (2–3 часа)

Цели: honeypot, который реально срабатывает; лимит по IP; атомарная запись без потери истории; данные **вне** вебрута.

```php
<?php
declare(strict_types=1);
error_reporting(E_ALL);
ini_set('display_errors', '0');           // S10: больше не ломает JSON
header('Content-Type: application/json; charset=utf-8');

// --- данные вне public_html ---
$dataDir = dirname(__DIR__) . '/data';    // /home/<user>/data
if (!is_dir($dataDir)) { mkdir($dataDir, 0750, true); }

// --- только POST ---
if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    http_response_code(405);
    echo json_encode(['success' => false, 'message' => 'Только POST запросы']);
    exit;
}

// --- honeypot: поле «website» реально есть в форме и скрыто CSS ---
if (!empty($_POST['website'])) {
    echo json_encode(['success' => true, 'message' => 'Спасибо за вашу заявку!']);
    exit;
}

// --- время заполнения: form_ts ставится при РЕНДЕРЕ страницы ---
$formTs = (int)($_POST['form_ts'] ?? 0);
if ($formTs === 0 || (time() - $formTs) < 2) {
    echo json_encode(['success' => true, 'message' => 'Спасибо за вашу заявку!']);
    exit;
}

// --- лимит: не более 3 заявок с одного IP за 10 минут (flock) ---
$ip    = $_SERVER['REMOTE_ADDR'] ?? '0.0.0.0';
$rateF = $dataDir . '/rate_' . sha1($ip) . '.json';
$fh    = fopen($rateF, 'c+');
if ($fh) {
    flock($fh, LOCK_EX);
    $raw  = stream_get_contents($fh) ?: '[]';
    $hits = array_values(array_filter(json_decode($raw, true) ?: [],
        fn($t) => (int)$t > time() - 600));
    if (count($hits) >= 3) {
        flock($fh, LOCK_UN); fclose($fh);
        http_response_code(429);
        echo json_encode(['success' => false, 'message' => 'Слишком много заявок, попробуйте позже']);
        exit;
    }
    $hits[] = time();
    ftruncate($fh, 0); rewind($fh);
    fwrite($fh, json_encode($hits));
    flock($fh, LOCK_UN); fclose($fh);
}

// --- валидация: htmlspecialchars только при ВЫВОДЕ в HTML (S9) ---
$name    = trim((string)($_POST['name'] ?? ''));
$phone   = preg_replace('/\D/', '', (string)($_POST['phone'] ?? ''));
$email   = trim((string)($_POST['email'] ?? ''));
$message = trim((string)($_POST['message'] ?? ''));

// --- запись: NDJSON append-only + LOCK_EX (вместо перезаписи JSON, S2) ---
$line = json_encode([
    'timestamp' => date('Y-m-d H:i:s'),
    'ip'        => $ip,
    'name'      => $name,
    'phone'     => $phone,
    'email'     => $email,
    'message'   => $message,
], JSON_UNESCAPED_UNICODE) . PHP_EOL;
file_put_contents($dataDir . '/requests.ndjson', $line, FILE_APPEND | LOCK_EX);

// --- письмо админу (без Cc и без автоответа — см. S4) ---
$headers = "From: noreply@xn--80ahhialrcec8b1i.xn--p1ai\r\n"
         . "MIME-Version: 1.0\r\n"
         . "Content-Type: text/plain; charset=UTF-8\r\n";
if ($email !== '' && filter_var($email, FILTER_VALIDATE_EMAIL)) {
    $headers .= "Reply-To: $email\r\n";
}
$body = "Новая заявка с сайта\n\n"
      . "Имя: $name\nТелефон: $phone\nEmail: $email\nСообщение: $message\nIP: $ip\n";
@mail('vvnovikov30@yandex.ru',
      '=?UTF-8?B?' . base64_encode('Новая заявка с сайта ОдноЭтажники.РФ') . '?=',
      $body, $headers);

echo json_encode(['success' => true, 'message' => 'Спасибо за вашу заявку!'], JSON_UNESCAPED_UNICODE);
```

Почему NDJSON вместо «прочитать JSON → дописать → перезаписать»: сейчас (S2) один битый файл уничтожает историю; append-only строки переживают любые гонки.

**Сниппет проверен локально** (`php -l` — чисто; прогон на `php -S 127.0.0.1:8099`):

| Запрос | Ответ | Запись создана |
|---|---|---|
| `GET /send-email.php` | `405` | нет |
| `POST` без `form_ts` | `{"success":true}` (фейковый) | **нет** |
